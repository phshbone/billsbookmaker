UI terms reference

Screen / View: A full page or major app area.

Panel: A section inside a screen.

Card: A contained item with title, content, and actions.

Drawer: A storage-style area for related cards.

State: What the app remembers.

LocalStorage: Browser-only save storage. It does not sync between devices.

Single-file app: One HTML file containing structure, style, and behavior.

app hierarchy help

App: The whole product.

Primary Sections: Main tabs or drawers.

Screens: Individual pages or views.

Components: Reusable cards, forms, buttons, modals, drawers, tab bars.

User Flow: What happens in order.

Data: What must be saved.

Actions: What the user can do.

Rules: Logic the app must follow.

prompt structure

For stories, focus prompts on characters, scenes, plot threads, setting, continuity, and unresolved gaps.

For apps, focus prompts on goal, screens, navigation, components, saved data, actions, style, and delivery constraints.

The main AI Prompt button automatically changes its instructions based on Storyboard or App Builder mode.

single HTML workflow

1. Build or edit one HTML file.
2. Save it as index.html.
3. Upload/replace it in GitHub.
4. Commit changes.
5. GitHub Pages serves the updated app.

App data saves locally. Export JSON before switching projects/devices; import JSON to restore it.

Built-in AI with protected API keys would require a backend later. The current AI/export tools cost nothing because they only prepare text for the AI service you already use.
